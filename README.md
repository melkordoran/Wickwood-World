# Wickwood

A fog-bound old forest where every trail is marked by lanterns. Wickwood is a P256 world (5.12 × 5.12 km) for Axis / Active Worlds, built for walking and flying. Every model, texture, avatar and terrain height is generated by the pipeline in this repository.

The generated snapshot holds 18,524 objects. The trees, understory, lanterns, a hamlet, a tarn, a hilltop beacon and seven destinations all come from 66 original procedural models. No AlphaWorld core or UberPath assets are used.

## Source snapshot

This repository is a public source export prepared on 2026-09-22. It contains:

- **Design:** `DESIGN.json` and `world-spec.json`.
- **Pipeline:** the complete generator and QA pipeline in `pipeline/`.
- **Atlas:** the browser atlas frontend in `preview/`.
- **Generated snapshot:** `generated/`.

`generated/` holds the models (RWX and ZIP), 18 textures, two static avatars, the 512 × 512 terrain arrays, `scene.json`, a portable `properties.sqlite`, `world-attributes.json`, destinations and routes. `BUILD.json` records the SHA-256 of every file.

Server databases, account data, passwords, installation backups, deployment reports and frozen deployment releases are excluded.

The snapshot is byte-identical to the release deployed on the author's server, except for the object path in `world-attributes.json` and the build record in `BUILD.json`. Local endpoint references have been changed to `http://127.0.0.1:8080/wickwood/`; configure a client-reachable object path before installation. `PUBLIC-SOURCE.json` records the adjustments and the checks run on this export.

## Trails

Eight lantern-lit trails join the places. Each is a paved ribbon laid on terrain that the generator flattened under it. Grades are quantized to 2 % steps and change gradually.

| Trail | From | To | Length | Steepest grade |
|---|---|---|---|---|
| Hollow Lane | glade | hollow | 514 m | 2 % |
| Mistwater Path | glade | tarn | 494 m | 14 % |
| Beacon Climb | glade | beacon | 2,161 m | 6 % |
| The Rootwalk | glade | oak | 718 m | 2 % |
| Candle Road | hollow | circle | 558 m | 4 % |
| Shoreline Way | tarn | circle | 828 m | 8 % |
| The Mosswalk | oak | dell | 519 m | 4 % |
| Firefly Run | hollow | dell | 605 m | 6 % |

Lanterns stand every 20 m on alternating sides. Every second one carries a light, and every fifth lit one flickers. Long trails also have wayshrines every 250 m.

## Atmosphere

Night fog with tinted colour (44, 54, 56) runs from 6 m to 135 m. Moonlight comes from the south-west, the ambient light is a cool grey, and lights reach up to 40 m. Water fills the tarn basin at level 0 with the generated `wk_water` texture. Flight, teleports and passing through avatars are enabled, and gravity and friction are normal.

## Generate locally

Use Python 3.11 or later with NumPy and Pillow. Rebuilding replaces `generated/`, so work in a disposable copy if you want to keep the supplied snapshot. The build is deterministic. With the Python, NumPy and Pillow versions recorded in `PUBLIC-SOURCE.json`, it reproduces the snapshot byte for byte, apart from the build time and duration in `BUILD.json`. Other library versions may encode textures or round terrain slightly differently.

```sh
python -m pip install -r requirements.txt
python pipeline/build.py            # regenerate generated/ and validate it
python pipeline/build.py --freeze   # also copy it to releases/<stamp>/ with FROZEN.json
```

The build fails if validation finds a problem. The checks cover:

- objects outside P256, and cells over budget
- missing models, and reader warnings
- trees on trails, and uneven building pads
- blocked or buried arrivals, and duplicate object numbers
- model parts floating more than 10 cm clear of the rest of their model

To view the browser atlas from a frozen release:

```sh
python pipeline/deploy_assets.py releases/<stamp> site/wickwood --manifest site/deploy-manifest.json
python pipeline/atlas_export.py releases/<stamp> build/atlas/data
python pipeline/deploy_atlas.py site/wickwood/preview site/atlas-manifest.json
python -m http.server 8000 --bind 127.0.0.1 --directory site
```

Then open `http://127.0.0.1:8000/wickwood/preview/`. The atlas redraws the published models, textures and terrain with Three.js. It is an approximation for orientation, not the native renderer. Its map view brightens the night lighting on purpose.

| Module | Role |
|---|---|
| `pipeline/wk_textures.py` | Tileable spectral-noise textures (256 × 256 JPEG) with a provenance record |
| `pipeline/wk_terrain.py` | Heightfield, lake, hills and dell, trail profiles and flattened trail corridors, terrain textures |
| `pipeline/wk_mesh.py`, `pipeline/wk_models.py` | Mesh builder and the model catalogue, exported as RWX in ZIP archives |
| `pipeline/wk_layout.py` | Places, trails, lanterns, signs, forest and understory placement |
| `pipeline/wk_qa.py` | Floating-part check used by the build, and a coplanar-overlap scan for flicker-prone faces |
| `pipeline/rwx_reader.py` | Strict RWX reader that re-parses every exported and downloaded model |
| `pipeline/build.py` | Runs the pipeline, validates, writes `BUILD.json`, and freezes releases |
| `pipeline/deploy_assets.py` | Copies only models, textures and avatars from a frozen release to an object path |
| `pipeline/verify_http.py` | Downloads every asset from an object path URL and proves it matches a release |
| `pipeline/atlas_export.py`, `pipeline/deploy_atlas.py` | Browser atlas data and publication |

## Installing on a server

These files are source content, not a backup of a running server. Installation needs your own Axis universe and world server and an import method you trust. The author's installation provisioned the world privately and applied `world-attributes.json`. It then imported the terrain rows and `scene.json` through a caretaker session, read every object and terrain sample back, and only then opened the world. That tooling belongs to the server installation and is not included here.

Before importing, review the following:

- the world name, P256 registration, capacity and caretaker (the scene uses owner and caretaker 1)
- the object path
- `CellLimit`: the settings use the classic code `11000`, which classic administrator sessions store as the 32,768-byte tier

Import only into an empty world. Serve only the models, textures and avatars from the object path; `pipeline/deploy_assets.py` does exactly that. Afterwards, `pipeline/verify_http.py` checks every asset over the real URL.

Asset-only changes need no server change when a new release's `scene.json`, terrain and `world-attributes.json` match the deployed ones. Publish them with `deploy_assets.py --update-from <deployed release>`. It replaces a file only if the published copy still matches the previous release, and swaps each one in atomically.
